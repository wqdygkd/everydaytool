# 抖音去水印下载工具 v3.2.0 视频解析逻辑分析

> 分析对象：`抖音去水印下载工具v3.2.0.exe`（PyInstaller 打包，Python 3.12）
>
> 分析目的：理解其链接解析、作品详情获取、用户作品分页、请求签名与数据提取规则，并在另一个软件中复现同等能力。
>
> 合规提示：本文仅用于学习、互操作与自有内容处理。请遵守抖音用户协议、robots 规则与著作权要求，不要用于批量抓取或传播他人作品。

## 1. 结论摘要

该软件的“视频解析”并不是解析网页 HTML，而是复刻抖音 Web 端的内部 JSON 接口：

1. 从分享链接中提取 `aweme_id`（作品 ID）、`sec_user_id`（作者 ID）或判断为用户主页。
2. 构造抖音 Web 端请求参数（浏览器指纹、时间戳、`uifid`、`verifyFp`、`fp` 等）。
3. 使用本地算法生成 `a_bogus` 签名。
4. 请求 `https://www.douyin.com/aweme/v1/web/aweme/detail/` 获取单个作品，或请求 `.../aweme/post/` 获取用户作品列表。
5. 从 `aweme_detail` / `aweme_list` 中提取视频多清晰度地址、图文原图、封面、音乐、统计信息等。
6. 优先选择 `v95-web-sz` 或 `v11-weba` 的播放地址，作为“无水印”下载地址；图文优先使用 `watermark_free_download_url_list`。

核心模块：

| 模块 | 作用 |
| --- | --- |
| `src/core/api.py` | 前端 API 桥接、流式分页、结果格式化 |
| `src/core/douyin_api.py` | 抖音接口、参数、Cookie、数据提取 |
| `src/core/utils/abogus.py` | `a_bogus` 签名算法 |
| `src/core/utils/dy_params.py` | `verifyFp`、`msToken`、`webid` 动态参数 |
| `src/core/cdp/douyin_cdp.py` | 真实浏览器 CDP 采集（默认优先路径） |
| `src/core/parser.py` | 仅作为失败兜底的模拟数据解析器，不含真实接口 |

## 2. 总体调用链

前端 `app.js` 调用：

```text
parse_link_stream(url, platform)
  -> API.parse_link_stream
     -> API._create_douyin_stream_func(url)
        -> parse_douyin_url(url)
        -> CDP 优先：DouyinCDPFetcher.fetch_video_detail / fetch_user_posts
        -> 失败回退：get_douyin_video_detail_sync / curl_cffi 分页请求
```

单作品（非流式）：

```text
API._parse_douyin_link(url)
  -> parse_douyin_url(url)
  -> 作品：get_douyin_video_detail(aweme_id, sec_user_id)
           -> get_douyin_video_detail_sync(...)
              -> build detail params + a_bogus
              -> GET /aweme/v1/web/aweme/detail/
              -> extract_aweme_info(aweme_detail)
  -> 用户：get_douyin_user_posts(sec_user_id)
           -> GET /aweme/v1/web/aweme/post/  (循环分页)
```

关键点：`src/core/parser.py` 中的 `DouyinParser.parse()` 只是 `_mock_work()` 模拟数据，不是真实解析逻辑。真实逻辑全部在 `douyin_api.py`。

## 3. 链接识别

### 3.1 直接 URL 规则

`_try_parse_direct_url(url)` 依次匹配：

| 正则 | content_type | 提取字段 |
| --- | --- | --- |
| `/user/([a-zA-Z0-9_-]+)` | `user` | `sec_user_id` |
| `/video/(\d+)` | `video` | `aweme_id` |
| `/note/(\d+)` | `note` | `aweme_id` |

匹配成功返回：

```python
{
    "sec_user_id": "...",   # user 时
    "aweme_id": "...",      # video/note 时
    "content_type": "user|video|note",
    "final_url": url,
}
```

### 3.2 短链判定

```python
if "v.douyin.com" in url or (
    "douyin.com/" in url and not url.startswith("https://www.douyin.com")
):
    # 走短链解析
```

短链解析顺序：

1. 先尝试直接正则。
2. 否则 `GET` 短链（`follow_redirects=True`，使用 `BASE_HEADERS`），读取最终 URL。
3. 最终 URL 再跑直接正则。
4. 失败则从 HTML 中匹配 `aweme_id` 和 `sec_user_id`。
5. 仍无 `sec_user_id` 时，用 iPhone UA 再请求一次。
6. 仍无且已有 `aweme_id` 时，调用作品详情接口，从 `aweme_detail.author.sec_uid` 获取。

### 3.3 已知限制

- `https://www.douyin.com/user/xxx?modal_id=123` 会被识别为用户主页，而不是弹出的单作品。
- 直接 URL 不包含 `/video/`、`/note/`、`/user/` 时无法识别，除非走短链重定向。

## 4. 单作品详情接口

### 4.1 请求

```http
GET https://www.douyin.com/aweme/v1/web/aweme/detail/
```

请求头（`BASE_HEADERS`）：

| Header | 值 |
| --- | --- |
| `accept` | `application/json, text/plain, */*` |
| `accept-language` | `zh-CN,zh;q=0.9,en;q=0.8,en-GB;q=0.7,en-US;q=0.6` |
| `priority` | `u=1, i` |
| `sec-ch-ua` | `"Microsoft Edge";v="149", "Chromium";v="149", "Not)A;Brand";v="24"` |
| `sec-ch-ua-mobile` | `?0` |
| `sec-ch-ua-platform` | `"Windows"` |
| `sec-fetch-dest` | `empty` |
| `sec-fetch-mode` | `cors` |
| `sec-fetch-site` | `same-origin` |
| `user-agent` | Edge 149 / Chrome 149 的 Windows UA |
| `referer` | `https://www.douyin.com/video/{aweme_id}` |

注意：详情请求使用 `BASE_HEADERS.copy()` 后只加 `referer`，不额外加 `uifid` 请求头。

### 4.3 响应处理

```python
result = response.json()
if result.get("status_code") == 0:
    aweme = result.get("aweme_detail") or {}
    info = extract_aweme_info(aweme)
else:
    # status_code / status_msg 判定 Cookie 是否过期
```

过期判定：

- `status_code in {10001, 10002, 10003, 10010, 10011, 10012, 10013}`
- 或 `status_msg` 包含 `expired`、`过期`、`invalid`、`失效`、`unauthorized`、`未授权`、`login`

### 4.4 实际探测结果

在无 Cookie 环境下直接请求详情接口，服务端返回：

```text
HTTP 403: Blocked by ArgusSecurityPlugin Uifid Not Found
```

这不是签名错误，而是缺少有效的 `UIFID` / 登录态。原软件默认启用 CDP（真实浏览器）就是为了绕开这一点。纯 HTTP 方案必须提供浏览器登录后的 Cookie，最好配合 `curl_cffi` 的 TLS 指纹。

### 5.2 分页

```python

while True:
    data = request(max_cursor)
    aweme_list = data.get("aweme_list", [])
    if not aweme_list:
        break
    for aweme in aweme_list:
        yield extract_aweme_info(aweme)
    if data.get("has_more", 0) != 1:
        break
    max_cursor = str(data.get("max_cursor", "0"))
    sleep(0.5)
```

### 5.3 TLS 指纹

流式路径使用：

```python
from curl_cffi.requests import AsyncSession
async with AsyncSession(impersonate="chrome146", timeout=30) as client:
    ...
```

原因：普通 `httpx`/`requests` 的 TLS 指纹容易被 403 拦截；`curl_cffi` 模拟 Chrome 的 JA3/JA4。请求头同时带 `uifid`。

## 6. CDP 浏览器采集路径

`src/core/cdp/douyin_cdp.py` 不生成签名，而是：

1. 启动本机 Edge/Chrome（远程调试端口，默认 9222）。
2. 打开 `https://www.douyin.com/video/{id}` 或 `/user/{sec_uid}`。
3. 通过 CDP `Network` 域监听响应，捕获：
   - `/aweme/v1/web/aweme/detail/`
   - `/aweme/v1/web/aweme/post/`
   - `/aweme/v1/web/user/profile/other/`
4. 直接读取响应 JSON，交给同一个 `extract_aweme_info()`。
5. 用户主页通过滚动触发分页；滚动不够时在页面上下文里用 `fetch()` 按 `max_cursor` 续采。

优点：签名、Cookie、TLS 指纹全部由真实浏览器自动完成。

缺点：需要浏览器窗口/登录态，速度慢，依赖 CDP 端口。

原软件默认 `cdp.enabled=true`、`cdp.auto_start=true`，所以它是“CDP 优先，接口兜底”。

## 7. `a_bogus` 签名算法

### 7.1 输入与输出

- 输入：参数字典（按请求顺序）和 User-Agent。
- 输出：160 字符的字符串，字符集为 `s4` 自定义 Base64 表。
- 生成过程含随机数，所以同一参数每次结果不同，但服务端可验证。

### 7.2 常量

```python
END_STRING = "cus"

S3 = "ckdp1h4ZKsUB80/Mfvw36XIgR25+WQAlEi7NLboqYTOPuzmFjJnryx9HVGDaStCe"
S4 = "Dkdpgh2ZmsQB80/MfvV36XI1R45-WUAlEixNLwoqYTOPuzKFjJnry79HbGcaStCe"
```

### 7.3 步骤

#### 1）UA 编码

```python
key = "".join(chr(int(x)) for x in (0.00390625, 1, 14))  # chr(0)+chr(1)+chr(14)
ua_rc4 = rc4_encrypt(user_agent, key)
ua_code = sm3_to_array(base64_custom(ua_rc4, S3))
```

#### 2）生成 12 字节随机串

`list_1`、`list_2`、`list_3` 各生成 4 字节：

```python
def random_list(b=170, c=85, d=0, e=0, f=0, g=0):
    r = random() * 10000
    v1, v2 = int(r) & 255, int(r) >> 8
    return [
        v1 & b | d,
        v1 & c | e,
        v2 & b | f,
        v2 & c | g,
    ]

string_1 = chars(list_1(170, 85, 45)) + chars(list_2()) + chars(list_3())
```

#### 3）参数与方法的 SM3 双重摘要

```python
params_array = sm3_to_array(sm3_to_array(urlencode(params) + "cus"))
method_array = sm3_to_array(sm3_to_array("GET" + "cus"))
```

注意：`params` 的键顺序必须和实际发送时一致；`urlencode` 使用同一实现。

#### 4）时间窗口

```python
start_time = int(time() * 1000)
end_time = start_time + randint(4, 8)
```

#### 5）组装 44 字节

```python
values = [
    44,
    end_time >> 24 & 255,
    0, 0, 0, 0, 24,
    params_array[21],
    method_array[21],
    0,
    ua_code[23],
    end_time >> 16 & 255,
    0, 0, 0, 1, 0, 239,
    params_array[22],
    method_array[22],
    ua_code[24],
    end_time >> 8 & 255,
    0, 0, 0, 0,
    end_time & 255,
    0, 0, 14,
    start_time >> 24 & 255,
    start_time >> 16 & 255,
    0,
    start_time >> 8 & 255,
    start_time & 255,
    3,
    int(end_time / 2**32),
    1,
    int(start_time / 2**32),
    1,
    len(browser_info),
    0, 0, 0,
]
```

#### 6）追加浏览器信息与校验字节

```python
browser_info = "|".join([
    inner_width, inner_height, outer_width, outer_height,
    0, screen_y, 0, 0,
    outer_width, outer_height, outer_width, outer_height,
    inner_width, inner_height, 24, 24, platform,
])
values += [ord(c) for c in browser_info]
values.append(xor_all(values))
```

重要细节：`ABogus.__init__(user_agent)` 调用 `generate_browser_info(None)`，所以 `platform` 参数是 `None`，最终浏览器信息以 `|None` 结尾。这一点必须复刻，否则签名不一致。

#### 7）RC4

```python
string_2 = rc4_encrypt(chars(values), "y")
```

#### 8）自定义 Base64

```python
bogus = base64_custom(string_1 + string_2, S4)
```

Base64 不是标准表，而是 `S4`；每 3 字节拆成 4 个 6-bit 值，末尾补 `=`。

### 7.4 伪代码（跨语言移植）

```text
sign(params, ua):
  uaCode = sm3(customB64(rc4(ua, "\x00\x01\x0e"), S3))
  pCode = sm3(sm3(urlencode(params) + "cus"))
  mCode = sm3(sm3("GETcus"))
  now = epochMillis()
  end = now + randint(4, 8)
  head = bytes44(now, end, pCode[21..22], mCode[21..22], uaCode[23..24], len(browser))
  body = head + asciiBytes(browser) + [xor(head + asciiBytes(browser))]
  return customB64(chars12() + rc4(body, "y"), S4)
```

本目录下的 `douyin_parser/` 是独立实现，默认零第三方依赖：

| 文件 | 说明 |
| --- | --- |
| `sm3.py` | 纯 Python SM3，已验证与 `gmssl` 一致 |
| `abogus.py` | `a_bogus` 完整实现，已与原字节码逐字节对齐 |
| `dy_params.py` | `verifyFp`、`msToken`、`webid` |
| `constants.py` | 请求头、接口、指纹、过期码 |
| `urls.py` | 链接识别、短链重定向、HTML 兜底 |
| `client.py` | 详情、用户作品、用户资料、Cookie |
| `extract.py` | 视频/图文/用户/收藏数据提取、画质选择、表格格式化 |
| `transport.py` | `urllib` + 可选 `curl_cffi` |
| `cli.py` | 命令行入口 |

### 9.1 基本用法

```python
from douyin_parser import DouyinClient

client = DouyinClient(cookie_file="cookies.json")

parsed = client.parse_url("https://v.douyin.com/xxxx/")
print(parsed)

if parsed["content_type"] in ("video", "note"):
    result = client.fetch_video_detail(parsed["aweme_id"], parsed.get("sec_user_id"))
    print(result["data"]["quality_list"][0]["download_urls"][0])
elif parsed["content_type"] == "user":
    result = client.fetch_user_posts(parsed["sec_user_id"], max_pages=1)
    print(result["total"])
```

## 10. 验证方案与结果

### 10.1 离线验证

运行：

```powershell
python validate_offline.py
```

本机结果：

```text
[PASS] SM3 implementation (known vectors + gmssl)
[PASS] a_bogus signature (90 differential cases)
[PASS] aweme/user extraction (7 differential cases)
[PASS] request parameters (4 parameter sets)
[PASS] URL classification (6 direct URLs + 5 HTML samples)
[PASS] formatted output schema (2 formatted items)

Summary: 6/6 passed, 0 failed
```

验证方式不是“看起来差不多”，而是：

- 从 `PYZ.pyz_extracted/src/core/utils/abogus.pyc` 加载原始 `ABogus` 类；
- 同时固定 `random()`、`randint()`、`choice()`、`time()`；
- 对 3 种 UA × 3 组参数 × 10 个随机种子，共 90 组，逐字符比较签名；
- 从 `douyin_api.pyc` 提取原始 `extract_*` 函数对象，对视频/图文/用户样例做深度相等比较；
- 从 `douyin_api.pyc` 提取原始 `_extract_sec_user_id_from_html`，用 5 组 HTML 样例比较 `sec_user_id` 提取结果；
- 从 `douyin_api.pyc` 提取原始参数构造函数，逐键比较两套作品列表参数；
- 从 `api.pyc` 提取原始 `_format_douyin_data`，比较最终表格字段。

没有原始字节码时，可运行：

```powershell
python validate_offline.py --skip-reference
```

此时会执行自包含回归测试。

### 10.2 在线验证

```powershell
python validate_live.py "https://www.douyin.com/video/730..." --cookie-file cookies.json --download-check
```

或用户主页：

```powershell
python validate_live.py "https://www.douyin.com/user/MS4wLjABAAAA..." --cookie-file cookies.json --max-pages 1
```

脚本会：

1. 识别链接；
2. 请求详情/用户作品；
3. 打印清晰度、图片数量、无水印地址；
4. `--download-check` 用 `Range: bytes=0-1023` 探测首个媒体地址是否可下载。

无 Cookie 的真实探测结果：

```text
HTTP 403: Blocked by ArgusSecurityPlugin Uifid Not Found
```

说明请求已经到达接口，但被登录态/风控拦截。原软件的应对方式是 CDP 浏览器路径；纯接口方式必须提供有效 Cookie，并建议安装 `curl_cffi`。

## 11. 在其他软件中集成

### 11.1 Python 项目

直接复制 `douyin_parser/` 目录，或把它作为子模块。核心只需要：

- `SM3`
- `RC4`
- 自定义 Base64
- `urlencode`
- HTTP GET

### 11.2 JavaScript / Go / Java 移植清单

必须按顺序实现：

1. SM3 摘要（不能换成 SHA-256）。
2. RC4（字节级，密钥为字符串的 `ord`）。
3. 自定义 Base64 表 `S3`、`S4`。
4. `generate_result` 的 6-bit 分组和补 `=` 规则。
5. `list_4` 的 44 字节固定模板。
6. `browser_info` 的 17 段拼接，最后一段是 `None`。
7. `urlencode` 的键顺序与实际请求完全一致。
8. 毫秒时间戳、`randint(4, 8)`、`random()*10000`。

最容易出错的地方：

- 参数顺序变了；
- `platform` 传了 `"Win32"` 而不是 `None`；
- 用了标准 Base64 表；
- 把 `urlencode` 的空格编码成 `%20` 而不是 `+`；
- 时间戳用了秒而不是毫秒；
- 先签名后追加参数（`a_bogus` 必须最后加，且不能参与自身签名）。

### 11.3 请求侧建议

- 详情接口：`httpx`/`requests` 即可，但必须有有效 Cookie。
- 用户作品列表：优先 `curl_cffi` + `impersonate="chrome146"`。
- 媒体下载：带 `Referer: https://www.douyin.com/` 和浏览器 UA。
- 失败重试：对 403/429 做退避；不要高频请求。

## 12. 风险与限制

1. 接口和风控会变：`a_bogus` 只是当前版本算法，抖音随时可能调整。
2. Cookie 是硬门槛：无 `UIFID`/`s_v_web_id` 时详情接口直接 403。
3. TLS 指纹：用户作品列表对普通客户端更敏感，`curl_cffi` 成功率更高。
4. 画质字段：`gear_name` 可能是 `1080p`、`normal`、`low` 等，原软件按名称/分辨率排序。
5. 图文实况：`live_video` 需要单独下载，原软件默认只下载静态图。
6. 音乐：`play_url.uri` 不一定是完整 URL。
7. 合规：仅处理自己有权使用的内容，遵守平台条款。
