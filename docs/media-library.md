# 媒体库（media-library）

> 状态：**已实现**（`tools/media-library/`）。可交互稿仍在 [`docs/preview/media-library.html`](./preview/media-library.html)，作视觉与交互基准。

## 1. 一句话定位

把本地的视频合集与图片套图整理成**一张可浏览的媒体卡片**：只读取原文件夹，索引与元信息写入 edt；原文件不移动、不改名、不写入。

## 2. 产品模型

| 概念 | 说明 |
| --- | --- |
| 合集 Collection | 一张卡片。可以只含视频、只含图片，也可以同时包含两者。 |
| 卡片根 Card root | 用户勾选为一张卡片的文件夹。卡片递归包含该文件夹下所有层级的媒体。 |
| 排除 Excluded | 已归入某张卡片的子文件夹，但被用户显式标记为不纳入；只影响索引，不影响原文件。 |
| 条目 Item | 合集里的一个视频或一张图片。只记录相对路径、文件名、大小、尺寸、时长、轻量指纹。 |
| 标签 Tag | 多对多，纯元信息。可新建，可筛选。 |
| 艺人 Artist | 独立档案：显示名、别名、简介与头像色。与合集多对多；别名归并到同一档案。 |
| 系列 Series | 合集之上的非独占分组。一个系列可引用多个合集，一个合集也可出现在多个系列里。 |
| 来源 Source | 一次导入的文件夹根。扫描、重扫、缺失检测都以来源为单位。 |
| 待整理 Inbox | 已导入但缺少艺人 / 标签 / 封面的合集，集中提示补全。 |

## 3. 数据落点（按 AGENTS 分层）

- `<data>/config/media-library/index.json`：合集索引、标签、来源、界面偏好。
- `<data>/config/media-library/artists.json`：艺人档案（`id` / 显示名 / 别名 / 简介 / 头像色）。
- `<data>/config/media-library/series.json`：系列（`id` / 名称 / 说明 / `collectionIds` 顺序 / 时间戳）。
- `<data>/config/media-library/collections/<id>.json`：单个合集的条目清单、`rootPath`、`excludedPaths` 与元信息。重扫时按这两项保持用户选择的卡片边界与排除项。
- `<data>/cache/media-library/thumbs/`：封面、缩略图、视频首帧。可再生，可整体清理。
- `<data>/cache/media-library/scans/`：最近扫描报告。可再生。
- 原文件：**不动**。不生成 sidecar，不写入原目录。

`artists.json` 与 `series.json` 都带版本号，读取时做旧数据兜底；写回仍走 `json-store` 的临时文件 + rename 原子写。

```json
{

  "artists": [
    {
      "id": "artist-lin-jia",
      "name": "林嘉",
      "aliases": ["Lin Jia", "林佳"],
      "bio": "纪录片与剧情短片导演。",
      "color": 3,
      "createdAt": "2025-11-14T10:00:00.000Z",
      "updatedAt": "2025-11-14T10:00:00.000Z"
    }
  ]
}
```

```json
{
  "version": 1,
  "series": [
    {
      "id": "series-mist-trilogy",

```

## 4. 扫描、确认与重扫

### 4.1 导入流程

1. 选择根目录。
2. 只读扫描，展开完整目录树；此阶段不写入索引。
3. 在确认页勾选文件夹，决定生成哪些卡片。
4. 确认后写入 `rootPath`、`excludedPaths` 与条目索引。
5. 进入资料库，卡片标记为“待整理”。

导入弹窗四个阶段都**不响应遮罩点击**：点到弹窗外的边缘不会关闭，避免误触丢掉扫描进度与已勾选的卡片 / 排除项。只能通过右上角关闭按钮、底部“取消 / 完成”或 `Esc` 退出。

### 4.2 卡片归属规则

- 任意层级的文件夹都可以设为**卡片根**；选中后递归包含其所有层级的视频与图片。
- 同一文件只能属于一张卡片：卡片根不能互相嵌套。父文件夹被选为卡片后，其子文件夹不能再单独成卡；先取消父卡片，才能拆分。
- 若父文件夹下已有子卡片，直接勾选父文件夹会把这些子卡片合并为父文件夹的一张卡片；合并不改变已有排除项。
- 父卡片内的子文件夹可标记为**排除**。排除会作用于整棵子树，例如排除 `花絮` 后，`花絮/原始素材` 也不会进入该卡片。
- 排除 / 恢复都以整棵子树为单位，并清理子树内多余的逐项排除，避免恢复后留下不可见状态。
- 排除只影响 edt 的索引，不移动、不删除、不重命名原目录。
- 未归入任何卡片的媒体会在右侧汇总为“未纳入”，默认不生成卡片；用户可回到目录树重新选择。
- 快捷操作：按一级文件夹预选、合并整棵目录为一张卡片、清空选择。
- 右侧始终显示将生成的卡片数、视频 / 图片总数与体积；没有选择时确认按钮禁用。

### 4.3 重扫

同一目录同时含视频与图片时，生成“混合”卡片。扫描按 `mtime + size` 判断新增 / 修改 / 缺失；缺失只标记，不自动从磁盘删除，也不自动移除合集。首次导入自动扫描；之后标题栏“重新扫描”和来源页按来源重扫。重扫沿用合集保存的 `rootPath` 与 `excludedPaths`，不重新猜测卡片边界。

预览中跳过的内容：隐藏文件、`Thumbs.db`、`.DS_Store`、临时文件、无法识别的扩展名。

## 5. 艺人与系列

两者都解决“看过之后怎么再找到”的问题，但不共享同一种模型：艺人回答“这是谁的作品”，系列回答“这批作品为什么放在一起看”。因此艺人是**独立主页 + 页内筛选**，系列是**合集的引用层**，都不把用户送回资料库的全局筛选。

### 5.1 艺人主页

艺人不是“资料库的筛选快捷方式”，而是独立的一级页面。

- 点击艺人卡片进入 `#artists/<artist-id>`，保留在艺人上下文，不跳回资料库。
- 页面上方是**艺人档案**：头像色、显示名、别名、简介、合集 / 视频 / 图片 / 体积统计，以及“编辑资料”。
- 页面下方直接是**该艺人的作品筛选区**：搜索、全部 / 视频 / 图片 / 混合、标签、排序，结果仍以合集卡片呈现。
- 艺人页的筛选状态只属于当前艺人页，不写入资料库的全局筛选，也不改变资料库的 URL 参数。
- “编辑资料”可维护显示名、别名与简介。别名用逗号分隔；别名若与另一艺人档案相同，保存时**合并两位艺人**，合集引用保留，原文件不动。
- 艺人卡片显示“N 个别名”；别名匹配同样用于资料库的艺人筛选，避免同一艺人的不同写法被拆开。
- `#artists/__none` 是“未指定艺人”页：同样有筛选与作品网格，顶部提供“去补全”入口。

#### 版面

- 顶部返回链接“全部艺人”回到 `#artists`，不回到资料库；艺人页内的搜索、类型、标签与排序在离开该页时重置，不写回 URL，也不污染资料库状态。
- 档案区是一块 `raised` 表面：64px 头像色圆、18px 显示名、别名行、最长 720px 的简介、统计行；右上角只放“编辑资料”。统计依次为合集 / 视频 / 图片 / 体积，全部按当前艺人的有效作品实时计算。
- 档案区下方是一段“作品”区，不再重复资料库的 billboard。工具条顺序固定为：页内搜索 → 全部 / 视频 / 图片 / 混合 → 标签 → 结果数 → 排序 → 清除筛选。窄宽时允许换行，但搜索框始终在最前。
- 结果复用资料库的合集卡片，不新增“艺人专用卡片”。没有结果时给空状态与“清除筛选”，不使用弹窗。
- 页内所有筛选只写 `state.artistQuery / artistType / artistTag / artistSort`，不写资料库的 `q / tag / artist / type`。资料库自己的筛选仍由 `#library` 的查询参数驱动，两套状态互不回写。

#### 编辑与合并

- “编辑资料”展开行内面板，维护显示名、逗号分隔的别名与简介；保存前只校验显示名非空。
- 别名比较先做 `trim`，再做大小写不敏感匹配；展示仍保留用户输入的写法。空别名、与显示名相同的别名会被丢弃，重复别名去重。
- 保存时若别名命中另一艺人档案，执行合并：保留当前档案的 `id` 与显示名，吸收被合并档案的显示名和全部别名，把合集中的旧名字改写为当前显示名，然后删除被合并档案。
- 合并只改 `artists.json` 与合集的艺人引用；合集、条目索引、缩略图、系列引用和原文件都不动。合并后立即重算艺人列表与当前艺人作品列表。
- 合并不可在预览里撤销属预览限制；正式版可在保存前给一次“将合并 N 位艺人”的确认，文案必须列出被合并的名字。

#### 状态与空值

- 合集没有艺人时归入“未指定艺人”，不计入任何具名艺人；在 `#artists/__none` 里可以逐张去补全。
- 艺人可以暂时没有作品（例如先建档案、后导入合集）；此时档案区正常显示，作品区为空状态，不隐藏艺人。
- 艺人页不提供“删除艺人”主操作，避免误删档案。正式版若要支持，必须先确认合集的艺人引用如何处理；默认只清空引用，不删合集。

### 5.2 系列

系列是**合集之上的非独占引用层**，不是文件夹，也不是新的媒体容器。

- 一个系列可引用多个合集；一个合集也可同时出现在多个系列里。系列不复制文件、不改动合集归属、不写原目录。
- 系列列表展示封面拼贴（取前三个合集；不足三个按实际数量铺满）、名称、说明、合集数、视频 / 图片数与更新日期。
- “新建系列”填写名称与一句说明后创建；创建完成直接进入系列详情，继续添加合集。
- 系列详情顶部是系列档案与操作：添加合集、编辑系列、删除系列；下方是系列内合集卡片。
- 编辑系列可维护名称与说明；删除系列只删除 `series.json` 中的分组记录，系列内合集、索引、缩略图与原文件全部保留。
- “添加合集”打开可搜索的选择器，支持一次勾选多个合集。已在系列中的合集显示“已在系列”并锁定，避免重复添加。
- 从系列移出使用卡片右上角的移除按钮；只移除引用，不删除合集。
- 系列内顺序按 `collectionIds` 保存，当前按添加顺序展示；正式版可在此之上加拖拽排序，不改变数据模型。

#### 版面

- 系列列表使用 `auto-fill / minmax(300px, 1fr)` 的卡片网格，间距 14px；卡片封面高 126px，用前三个合集封面拼成 1 / 2 / 3 格拼贴，不足三个按实际数量铺满，空系列显示占位。
- 系列卡片信息固定为：名称（14px，单行省略）、合集数（右上角胶囊）、说明（最多两行）、更新时间与总体积。视频 / 图片数放在说明下方或统计行，不与名称抢行。
- 系列详情是一块 300px 封面 + 档案区的两栏 hero；窄于 1120px 时改为单列、封面高 150px。操作顺序固定为：添加合集（主操作）→ 编辑系列（次操作）→ 删除系列（危险文本按钮）。
- “系列内合集”继续使用资料库的合集卡片；卡片右上角只在系列详情里出现“从系列移除”，不把“删除合集”混进系列操作。
- 系列本身没有独立封面编辑，首版直接用成员封面的拼贴；如果后续需要自定义封面，应作为 `series.cover` 字段新增，不改 `collectionIds`。

#### 添加与移除

- “添加合集”打开一个可搜索的多选对话框：列出所有合集，显示封面、标题、艺人、类型与条目数；已在系列中的行显示“已在系列”并锁定，不参与本次保存。
- 选择器支持一次勾选多个，保存时按当前顺序追加到 `collectionIds`；后端要去重、校验合集存在，并拒绝空名称的系列。
- 系列详情页的移除按钮只删除该 `collectionId` 引用；被移出的合集仍在资料库、仍可被其他系列引用。
- 删除系列只删除 `series.json` 中的记录；不级联删除合集、不清理缩略图、不触碰原文件。
- 从媒体库移除合集时，后端必须在同一事务性写入里从所有系列的 `collectionIds` 中摘掉该 id；系列因此变空时保留系列并显示空状态，不自动删除系列。
- 添加选择器里的空结果、全量已添加、搜索无匹配都要有明确文案；保存按钮在有新增选择前禁用。

## 7. 视觉方向

继承 edt 的 Command Deck：透明外壳、单一内容表面、98px 竖脊、品牌蓝只负责动作与选中。媒体内容自己承担色彩与冲击力；界面不抢戏。

- 资料库首屏：一块“最近导入”billboard + 右侧“继续观看”，下面直接进入合集网格。横向空间优先，纵向留给内容。
- 艺人页是“档案 + 作品”两段式：档案区只放身份、别名、简介与统计，作品区直接给筛选和卡片，不在艺人页重复资料库的 hero。
- 系列页是“编辑式拼贴”：系列卡片用前三个合集封面拼成横向条带；系列详情用一块封面 + 档案区，下面继续复用合集卡片，不为系列另造一套卡片语言。
- 导入确认页是两栏工作台：左侧目录树负责选择与排除，右侧只核对最终卡片、数量与未纳入媒体；不使用层层嵌套的对话框。
- 封面是**占位海报**（几何构图 + 标题排版），不是伪造的照片。真实导入后换为首帧 / 首图，也允许用户指定封面。海报语言刻意保持编辑感，避免“渐变占位块”的临时感。
- 详情页是“放映室”：首屏大封面，下面视频 / 图片 / 信息三页。播放器与图片灯箱局部转入深色，不把整个应用切成暗色主题；播放器控制条保留“外部播放”，用于调起系统播放器兜底。
- 卡片上直接露出类型、条目数、艺人、年份、大小与最多两个标签；更多标签折叠为 `+N`。
- 所有“原文件不动”的承诺在导入、编辑、来源三处各出现一次，但都用一句话，不做说明墙。

## 8. 已确认决策

1. **卡片边界**：导入确认页展示完整目录树，任意层级文件夹都可勾选为一张卡片；支持子目录排除。
2. **播放方式**：应用内使用 Video.js v10，同时提供外部播放器兜底；格式覆盖尽量完整，但不承诺 Chromium / 系统解码器不支持的编码。
3. **剧集结构**：v1 只做“合集 → 视频列表”，不引入季 / 集 / 特别篇字段。
4. **艺人与标签**：一个合集允许多个艺人；艺人拥有独立档案（显示名 / 别名 / 简介），别名需要合并；标签支持颜色与分组。
5. **删除语义**：从媒体库移除只删除索引与缩略图缓存，绝不删除原文件。
6. **规模**：不设硬上限；索引分片、缩略图队列与虚拟列表按大库设计。
7. **封面策略**：自动取视频首帧 / 套图第一张，之后允许手动更换。
8. **设计规范**：严格使用 `DESIGN.md`；媒体内容标题回到 18px 工具页上限，不新增 20–22px 令牌。
9. **艺人页**：艺人卡片进入独立主页，不跳资料库；顶部维护艺人资料，底部直接筛选作品。
10. **系列**：系列是合集的非独占引用层，可新建、编辑、删除、批量添加与移出合集；删除系列不删除合集或原文件。

## 9. 预览怎么操作

- 资料库 → 右上“导入文件夹” → 点击虚线框（预览模拟选中 `D:\Incoming\2025-11-14`）→ 开始扫描 → 确认合集 → 在资料库中查看。
- 确认页：勾选任意层级文件夹设为卡片；勾选父卡片后，子目录显示“归入 `<父卡片名>`”，逐行可“排除 / 恢复”。已有子卡片时再勾选父文件夹，会提示并合并为一张。右上“按一级文件夹 / 合并为一张 / 清空”可快速切换方案。

## 11. 正式实现时的映射

- 工具定义：`tools/media-library/index.ts`，`subRoutes` 对应资料库 / 系列 / 待整理 / 标签 / 艺人 / 来源；艺人主页与系列详情作为子路由，不使用弹窗。
- 前端：`renderer/ipc.ts` 唯一 helper；页面只经 IPC 调后端，不 import backend。
- 后端：`tools/media-library/backend/` 放扫描、目录树、指纹、封面提取、卡片归属校验、艺人档案与系列存储；平台层 `backend/utils/json-store.ts`、`data-layers.ts`、`path-guard.ts` 复用。导入确认结果由后端再次校验“卡片根不嵌套 / 排除路径仍在根内”，不能只信前端。
- 艺人：以 `artists.json` 的档案为唯一来源；保存别名时由后端做 `trim` + 大小写不敏感匹配与合并，合并只改合集里的艺人引用，不删除合集。艺人页筛选在渲染层组合索引，不写回全局筛选。
- 系列：以 `series.json` 的 `collectionIds` 为唯一来源；后端校验合集存在、去除重复引用，删除系列只删分组记录。合集可被多个系列引用，系列不参与扫描与文件归属。从媒体库移除合集时同步裁剪所有系列的引用。
- 播放：Video.js v10 播放器独立成组件，只接受后端给出的本地文件 URL；关闭工具时停止播放并释放对象 URL。外部播放器经主进程 `shell.openPath` 调起。
- 缩略图：后台队列 + 并发上限；缓存清理后由 `registerCacheIntegrityHandler` 触发重生成或回退到海报。
