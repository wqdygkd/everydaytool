# yunshu-uninstall（云枢卸载）

移除云枢 / eagleyun SASE 客户端的全部已知残留：launchd 服务、运行进程、文件与目录、登录/系统钥匙串里的根证书。
由同名 CLI 脚本（[`scripts/uninstall-yunshu.sh`](../scripts/uninstall-yunshu.sh)）的清单与判定逻辑搬进应用，做成可重复使用的一键页面。

## 定位

- 只服务这一个客户端，不做通用卸载器：清单写死在 `backend/services/targets.ts`，运行期不接受任何外部路径。
- 删除去向是**系统废纸篓**（Finder 可拖回），不是永久删除；`--purge` 那种模式在 GUI 里不提供。
- 需要 root 的项（`/Applications`、`/Library`、`/opt`、root 所有的临时文件）合并成**一次**管理员授权执行；用户级项走 `shell.trashItem`。

## 数据模型

| 概念 | 位置 | 说明 |
| --- | --- | --- |
| 目标清单 | `backend/services/targets.ts` | 文件 23 条（含末段通配符）、launchd 3 个、进程匹配 2 条、证书 1 张、仅提示 1 条 |
| 扫描产物 | `ResidueScan`（`shared/yunshu-uninstall.ts`） | `items[]` + `totalBytes` + `blocked[]`，主进程内存缓存 |
| 条目 | `ResidueItem` | `id` 只在本次扫描内有效，**清理只认 id，不认路径**；`exists` 表示该声明目标在本机是否存在 |
| 清单口径 | `scanResidue()` | **每个声明目标都出一行**：存在的给出路径与体积、可勾选；不存在的标注「不存在」、不可勾选、不参与统计与清理 |
| 进度事件 | `EVENT_PROGRESS` | 单向 broadcast，逐项 `running / done / failed` |

无持久化：不写 config、不写 cache，不进 `shared/data-layers.ts`（`pnpm data-layers:check` 因此不受影响）。

## 关键事务

1. **扫描**：`scanResidue()` 顺序扫服务 → 进程 → 文件 → 证书，体积用 `du -sk`（并发）后按「组顺序 + 体积降序」排序，排序**之后**才统一编号，保证 id 与展示顺序一致。
2. **清理**：`cleanResidue(ids, lastScan)` 按同一顺序执行。
   - 用户级文件：`shell.trashItem()`，走系统废纸篓、`放回原处` 可用。
   - 需要 root 的项：拼成一个 bash 脚本写到 `app.getPath('temp')/yunshu-clean-<ts>.sh`（0700），再用 `osascript -e 'do shell script "/bin/bash …" with administrator privileges'` 执行一次；脚本用 `@@OK:<id>` / `@@FAIL:<id>:<原因>` 回传逐项结果，主进程据此更新状态。
   - 管理员脚本里搬进废纸篓的项会 `chown -R <uid>`，否则清倒废纸篓时会被系统反复要密码。
3. **核对**：清理后立刻重扫，渲染层按 `path` 比对——报成功但路径仍在的条目降级为「仍存在，需复查」，不粉饰。

## 已知坑

- **id 会随重排变化**：清理后若用重扫结果替换列表，旧 id 的 status 会错位到别的行。当前实现保留「本次清理记录」，只有「重新扫描」才刷新列表，状态按 id 写入。
- **`security find-certificate` 查不到不等于不存在**：该命令在没匹配时也退出 0，必须判输出里有没有 `BEGIN CERTIFICATE`；锁定状态的钥匙串仍可读证书，所以扫描不会卡住，但**删除**需要解锁。
- **证书指纹**：只在 SHA-256 与 `targets.ts` 里记录的已知值一致时才允许自动删除，不一致只提示（可能同名但另一张）。
- **`launchctl bootout` 对未加载的服务返回非 0**：脚本里用 `launchctl print` 复检真实状态，不能拿退出码当结论。
- **`with administrator privileges` 被取消**：`osascript` 以 `-128 / User canceled` 失败，此时所有管理员项标记为「已取消管理员授权」，不重试、不静默。
- 系统 NE 配置（`/Library/Preferences/com.apple.networkextension.plist`）只作为「仅提示」条目出现，工具从不改动系统文件。

## 验收手法
```bash
pnpm typecheck && pnpm lint && pnpm data-layers:check
```

手工验证（需要真机残留，或在测试机上造几个假路径后改 `targets.ts`）：

1. 进工具 → 清单**把清单里所有目标都列出来**（3 个服务 + 2 类进程 + 23 条路径 + 2 个钥匙串），存在的一行给出路径、体积、可勾选；不存在的一行标「不存在」、复选框禁用、组头记作「N 项存在 · M 项不在」。顶部 statusline 左端是「N 项待清理」，右端是「可清理 X 项 · 体积 · K 项不存在」。**未清理前工具条左端没有筛选控件**。
   在干净的机器上，整屏会以「不存在」行为主——这是刻意的：清单本身就是核查表，缺什么比多什么同样重要；同组内存在的项排在前。
2. 点工具条右端的「清理 N 项 · X GB」→ 出现一次总确认；含系统目录项时随后弹**一次**管理员授权。
3. 完成后：逐行状态点变绿（失败为红并保留勾选），statusline 改成「已清理 N 项」，toast 汇总；此时工具条左端才出现「只看未完成（K）」，勾上只留待办、清空回到完整记录；清单本身保留为本次执行记录，点「重新扫描」才刷新。
4. 打开废纸篓：条目在，能拖回原处（系统目录项需手动拖，`放回原处` 对脚本搬入项不可用）。
5. 若钥匙串里有该证书：清单末尾出现「需要手动处理」，指纹完整显示；点「打开钥匙串访问」应直接拉起钥匙串访问；点「复制」应把带冒号的 SHA-256 放进剪贴板。
6. 窗口收窄到 1100px 时工具条仍不换行：筛选 → 已选计数 → 在废纸篓中显示 → 重新扫描 → 主操作，溢出时先压「已选」与主操作宽度，不折叠筛选。

## 视觉

沿用 DESIGN.md 的 Command Deck，骨架是 **列表工作台的单页变体**：`ToolSurface` 的三条带——48px 工具条 → 分组清单 → 31px statusline。没有第二条 header、没有左栏、没有竖脊。

清单**整体内缩 10px**（`padding: 10px 10px 18px`），组头因此是圆角小节（`--radius-sm` + `--color-fill`）而不是通栏色带，行 hover 也带同一圆角。这一条与 §8.4「表格直接占用表面」不同，理由是本页主体是清单而非表格：没有列头与外框，内容贴边会让每一行都像压在表面边框上。

> **为什么不是表格**：23 条条目是异质的（launchd 标签、PID、系统路径、`~` 路径、证书），列宽对齐在这里没有收益，"组"才是有用的信息——一个 daemon 和一个 881 MB 的引擎目录不该占同样的视觉重量。所以主体是四段清单，每段一个组头（名称 + 计数 + 体积 + 组内全选）。
>
> **为什么不用「处理控制台」**：那个骨架要求左栏承载参数与主操作；本工具左侧只有几行摘要，撑不起 360px 一列，而任务是一条流水线（扫描 → 勾选 → 清理），数据与动作都在同一栏里。

**标题栏右上角是空的**（DESIGN §5.3 的 The No Buttons Rule）：本页不向 `#app-topbar-actions` / `#app-topbar-state` 注入任何内容。

| 元素 | 落点 | 理由 |
| --- | --- | --- |
| 主操作「清理 N 项 · X GB」 | 48px 工具条最右端（`type="primary"`） | 列表类工具的主操作归工具条右端（§5.3） |
| 低频动作「重新扫描」 | 工具条右端，主操作左侧（`UiButton` default 32px） | 与 34px 分段控件同高；24px 小按钮并排会明显不齐 |
| 次操作「在废纸篓中显示」 | 工具条右端，`UiIconButton icon="external"` | 图标按钮 + `label`，不占文字宽度 |
| 选择 | 每行复选框 + 组头「全选」（三态） | 选择是清单自身的事；未选中时不显示「已选 N / M」 |
| 「只看未完成」 | 工具条左端，复选框，仅在一次清理后出现 | 动手前「全部 / 待清理 / 已完成」三档显示的是同一屏，属于无用的筛选；只有跑过之后待办与日志才需要分开 |
| 运行状态（点 + 文字）与扫描时间 | statusline 左端 | 状态与合计同处一行，1 行成本 |
| 合计项数 / 体积 / 需授权 / 被拦下条数 | statusline 右端 | 低频数据 |

### 需要手动处理区

列表末尾固定一段收尾区：有需要动手的条目时叫「需要手动处理」（警示色组头），否则叫「无需处理」（灰色）。

- **根证书**（EagleCloud Root CA）：一条带四步操作说明的引导块——「钥匙串访问」→ 选「登录」→ 类别选证书 → 搜 `EagleCloud` / `sase@eagleyun` → 右键「显示简介」核对 SHA-256 → 右键删除。目标钥匙串、指纹是否一致、为什么不自动删（指纹不符 / 系统钥匙串需授权 / 钥匙串锁定）都写在理由里；下面给出**完整的 SHA-256**（等宽、可断行）与「复制」按钮，右侧是「打开钥匙串访问」。
- **无需处理**：`/Library/Preferences/com.apple.networkextension.plist` 这类系统文件，写明“二进制已不在即无放行能力、属系统文件不改”，不提供按钮。

该区的条目 `removable: false`：不能勾选、不进清理事务、不占「已选」计数——工具对它们只做提示与引导，绝不代劳。
